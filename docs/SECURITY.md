# 安全邊界與發布前檢查 · Security & Pre-release Checks

> **一句話**：上傳一份資料，長出一棵技能樹 —— 讓進度看得見，讓每次完成都有成就感。
> **如何使用**：[主 README 如何使用](../README.md#how-to-use) · [AI 必問流程](../AGENTS.md) · [資料保存邊界](../MULTIUSER-ARCH.md) · [線上展示](https://bronya-0914.github.io/Skill-Tree/)

## 1. 安全模型

| 項目 | 現況 |
|---|---|
| 後端 | 無 |
| 帳號 | 無 |
| 資料存放 | 使用者瀏覽器的 `localStorage` |
| 網路請求 | 無外部 API、無追蹤 |
| 批改 | 前端執行 |
| 答案位置 | 前端資料檔 |

**結論**：這是一個適合公開練習與可視進度的工具，**不適合需要保密答案的正式評量**。前端要批改就必須讀得到答案，這是無法用前端技巧迴避的根本限制。

---

## 2. 資料邊界

| 資料 | 風險 | 因應 |
|---|---|---|
| 進度備份 JSON | 純文字、不加密、覆蓋式匯入 | 匯入前確認；不要放進公開資料夾 |
| 手寫草稿 | 存在瀏覽器，可能含個人筆跡 | 視為個人資料，不外分享 |
| 使用者提供的資料 | 可能受版權或保密約束 | 見 [`BOOK-REFERENCE.md`](../BOOK-REFERENCE.md) |
| 主題、光效、側板位置 | 低風險偏好資料 | 仍屬個人資料，隨備份一起處理 |

---

## 3. 版權與機密資料

- 取得一份資料 **不等於** 取得公開授權；可作為生成依據，不代表可以散布原文。
- 不要把原文全文、掃描頁、OCR 全文放進會發布的檔案或靜態站台。
- 個人筆記、成績、身份資料不要放進教材、範例或備份樣本。
- 靜態站台若以整個專案根目錄為根，**放在裡面的任何資料夾都可能被公開**；交付包、參考資料、交接文件都要在發布前排除或加忽略規則。
- 目前**尚未指定授權條款**；使用或散布前先向專案擁有者確認。

## 4. 對 AI 的約束

[`AGENTS.md`](../AGENTS.md) 訂下兩道阻塞式必問（資料、答題方式），另有：

| 規則 | 理由 |
|---|---|
| 不虛構來源 | 點亮的節點必須對應真實學習 |
| 三種題型之外的方式先說明落差 | 不得誤導使用者 |
| 不寫入未執行的部署成果 | 不得宣稱已上線或已推送 |
| 不索取或寫入 token | 憑證不進文件 |
| 不抄錄版權全文 | 法律風險 |

## 5. 發布前檢查清單

- [ ] 確認靜態根目錄範圍，排除參考資料、本機交接文件與私人備份
- [ ] 確認沒有本機絕對路徑、帳號、token、部署識別碼
- [ ] 確認沒有版權原文全文或掃描頁
- [ ] 確認授權條款已處理，或已明確標示尚未指定
- [ ] 確認文件寫的狀態與線上實際版本一致，不宣稱未執行的部署
- [ ] 確認 `references/` 類型的資料夾不在公開範圍
- [ ] 測試全綠、網站實測主流程、瀏覽器錯誤為零
- [ ] 確認對外操作（上傳、推送、發布）已取得明確授權

---

## 6. 回報問題

發現安全問題請在 <https://github.com/Bronya-0914/Skill-Tree/issues> 開立議題，寫清楚重現步驟與影響範圍；**不要在公開議題貼上私人備份內容或憑證**。

---

## 7. 已知限制

| 限制 | 說明 |
|---|---|
| 答案在前端 | 不能用於保密考試 |
| 備份不加密 | 拿到檔案就能讀 |
| 覆蓋式匯入 | 誤匯入會取代現有資料 |
| 無伺服端運算 | 無法做真正的保密批改或全班彙整 |
| 無授條款 | 法律狀態未定 |
| 靜態根目錄過寬 | 需人工排除，不能假設平台會自動過濾 |
