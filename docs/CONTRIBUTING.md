# 修改 SOP · Contributing

> **一句話**：上傳一份資料，長出一棵技能樹 —— 讓進度看得見，讓每次完成都有成就感。
> **如何使用**：[主 README 如何使用](../README.md#how-to-use) · [AI 必問流程](../AGENTS.md) · [學習包格式](../PACK_FORMAT.md) · [線上展示](https://bronya-0914.github.io/Skill-Tree/)
> **線上展示**：<https://bronya-0914.github.io/Skill-Tree/> · **儲存庫**：<https://github.com/Bronya-0914/Skill-Tree>
> **English**: [CONTRIBUTING.en.md](CONTRIBUTING.en.md)

## 1. 先分辨你要改的是什麼

| 想做的事 | 該走的路 | 要不要動程式 |
|---|---|---|
| 換一個課題 | 準備資料 → 交給 AI → 匯入學習包 ZIP | **不用** |
| 改某個節點的內文或題目 | 改學習包來源 → 重建 → 測試 → 實測 | 不用 |
| 改網站互動或版面 | 改前端 → 靜態檢查 → 逐屏實測 | 要 |
| 改文件格式 | 改驗證與 builder → 補測試 → 訂版本與遷移 | 要 |
| 改文件 | 改 Markdown → 檢查連結與雙語一致 | 不用 |

**最常見的誤解**：以為換課題要改程式。其實只要一份資料與 [`AGENTS.md`](../AGENTS.md) 的兩道必問。

## 2. 開發環境

| 項目 | 需求 |
|---|---|
| 執行環境 | Node.js（測試與 builder） |
| 前端 | 現代瀏覽器；可用任意靜態伺服器開 `index.html` |
| 套件 | 網站本身零安裝；不要用框架改寫 |
| 版本控制 | Git；提交前確認工作樹範圍 |

```bash
node --test tests/*.test.cjs
node --check app.js
node scripts/build-learning-packs.cjs
```

## 3. 課題與教材修改 SOP

1. 讀 [`AGENTS.md`](../AGENTS.md)：**先問資料**、**再問答題方式**，兩題都未完成不得生成。
2. 依 [`AI_TEACHING_GUIDE.md`](../AI_TEACHING_GUIDE.md) 走八階段。
3. 依 [`PACK_FORMAT.md`](../PACK_FORMAT.md) 寫來源檔；內容改動就遞增 `version`，在 `sourceNote` 寫明依據。
4. 節點 ID 保持穩定；要改 ID 先提醒使用者進度可能對不上。
5. 執行 builder 重建目錄檔與 ZIP，**不要手改生成檔**。
6. 執行測試；再到網站實測匯入、概念、答題、解鎖、點亮、重開後保存。
7. 若要雙語，依 [`I18N.md`](../I18N.md) 補整段與逐行 key。

---

## 4. 前端修改 SOP

1. 先評估影響範圍：DOM ID、狀態機、資料層、儲存鍵。
2. 視覺改動不得改變解鎖規則；點擊開合要同時顧桌機與手機。
3. 靜態檢查：語法、CSS 括號、資源可達、本地連結。
4. 執行期實測：起始頁、展開、深淺主題、側板開合、答題、批改、手機寬度，逐屏存證。
5. 缺陷閉環：現象 → 根因 → 修法 → 回歸；只記可重現的問題。
6. 尊重 `prefers-reduced-motion`；動畫只做必要的回饋。

## 5. 文件修改規則

- **定位一致**：網站不附帶既定教材；課題由資料生成。改定位就要改全部文件。
- **中英對照**：成對檔案 `.md`／`.en.md` 同步；單檔雙語兩節同步。
- **兩個網址**：每份文件都要有線上展示與儲存庫網址。
- **連結**：全部用相對路徑；改檔名要一併改所有參照。
- **不寫本機絕對路徑**、不寫 token、不寫未執行的部署成果。
- 新增給 AI 的規則，優先放進 [`AGENTS.md`](../AGENTS.md)，不要散在各檔。

---

## 6. 禁止事項

| 禁止 | 原因 |
|---|---|
| 手改 `catalog.js` 或 ZIP | 下次重建會被覆蓋 |
| 跳過 [`AGENTS.md`](../AGENTS.md) 的兩道必問 | 內容來源不可追溯、題目不符偏好 |
| 用了三種題型之外的答題方式卻沒說明 | 誤導使用者 |
| 把版權原文全文放進可發布檔案 | 法律風險，見 [`SECURITY.md`](SECURITY.md) |
| 未經授權推送、部署、發布 | 對外操作要先取得同意 |
| 只改主 README 的定位 | 文件集會自相矛盾 |

---

## 7. 提交前檢查

- [ ] 測試全綠、語法檢查通過
- [ ] 網站實測主流程，瀏覽器錯誤為零
- [ ] 深淺主題、手機寬度、公式不溢位
- [ ] 文件相對連結 0 斷、中英內容一致
- [ ] 兩個網址齊全、無本機絕對路徑
- [ ] 未含機密資料、未含生成檔的手改痕跡
- [ ] 明確知道哪些變動尚未提交、尚未部署

---

## 8. 驗收標準（R5）

| 層 | 通過條件 |
|---|---|
| 靜態分析 | 語法、括號、連結、資源皆無問題 |
| 執行期實測 | 主流程每屏有證據；缺點全數關閉或列為已知限制 |
| 缺陷閉環 | 每個問題都有現象、根因、修法、回歸結果 |
