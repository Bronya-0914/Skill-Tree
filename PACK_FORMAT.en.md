# Learning Pack Format · 學習包格式

> **One line**: upload one piece of material, grow one skill tree — progress you can see, achievement you can feel.
> **How to use**: [User guide](README.en.md#how-to-use) · [Mandatory AI prompts](AGENTS.md) · [Authoring method](AI_TEACHING_GUIDE.en.md) · [Live demo](https://bronya-0914.github.io/Skill-Tree/)

## 0. When to use this

This document defines the package in the middle of "user supplies material → AI generates → site imports". Before writing any JSON, confirm both mandatory questions in [`AGENTS.md`](AGENTS.md) are done: **obtain material** and **confirm the answer mode**. Format is only the carrier; the source and the preference decide the content.

All paths use `<topic-id>` as a placeholder. No specific subject or pre-existing course is implied.

---

## 1. Directory layout

```text
learning-packs/
  <topic-id>/
    topic.json
    nodes/
      <topic-id>.<node-key>.json
      ...
    README.md            (optional topic guide)
  <topic-id>.zip         (generated by the builder, for site import)
  catalog.js             (generated by the builder, read by the site)
```

| File | Produced by | Hand-editable |
|---|---|---|
| `topic.json` | AI / human | Yes |
| `nodes/*.json` | AI / human | Yes |
| `README.md` | AI / human | Yes |
| `catalog.js` | Builder | **No** |
| `<topic-id>.zip` | Builder | **No** |

After changing sources:

```bash
node scripts/build-learning-packs.cjs
node --test tests/*.test.cjs
```

## 2. `topic.json`

| Field | Type | Meaning |
|---|---|---|
| `schemaVersion` | number | Format version, currently `1` |
| `id` | string | Course ID: lowercase letters, digits, hyphens |
| `title` | string | Display name |
| `version` | number | Content version; increment on any content change |
| `language` | string | Primary content language |
| `attachTo` | string | Attach point, normally `start` |
| `description` | string | One-line summary of coverage |
| `nodes` | string[] | Node IDs; order is informational, unlocking follows `parents` |
| `sourceNote` | string | Source description; must state when no specific source was used |

`version` drives replacement: the site compares versions to decide whether to supersede existing content. It does **not** merge two courses automatically.

---

## 3. Node files `nodes/*.json`

| Field | Type | Meaning |
|---|---|---|
| `id` | string | Stable; changing it breaks existing progress |
| `title` | string | Node title |
| `kind` | string | Category tag used for styling or statistics |
| `minutes` | number | Suggested time |
| `parents` | string[] | Prerequisite node IDs; must exist in this course and form no cycles |
| `intro` | string | What problem this knowledge point solves |
| `content` | object[] | Segmented concepts, see below |
| `questions` | object[] | Practice items, 1–20 per node, any of the three item types |
| `passCount` | number | Correct answers required to pass; must not exceed item count |

### 3.1 `content[]` blocks

| `type` | Purpose | Required field |
|---|---|---|
| `heading` | Subheading | `text` |
| `paragraph` | Explanatory text | `text` |
| `formula` | Formula, explicitly broken into lines | `text`, using `\n` to prevent misaligned wrapping |
| `example` | Worked example | `text` |
| `tip` | Misconceptions / hints | `text` |

Break long formulas and long text **explicitly**. Formula boxes on the site do not wrap automatically; a single long line will overflow on narrow screens.

### 3.2 `questions[]` items (three types)

Each node has 1–20 items. `passCount` is the number of correct items required to pass and must be between 1 and the item count.

**(1) Multiple choice**

| Field | Type | Meaning |
|---|---|---|
| `prompt` | string | Stem |
| `options` | string[] | 2–6 options |
| `answer` | number | Correct option index, zero-based |
| `explanation` | string | Per-item explanation |

**(2) Numeric input**

| Field | Type | Meaning |
|---|---|---|
| `type` | string | Always `'input'` |
| `prompt` | string | Stem |
| `answers` | string[] | 1–8 accepted answers: integers, decimals, fractions, or expressions such as `sqrt(2)` and `pi` |
| `tolerance` | number | Optional, at most 0.01 |
| `explanation` | string | Per-item explanation |

Grading uses a standalone numeric expression parser and **never evaluates JavaScript**. It supports `+ - * / ^` plus `sqrt`, `sin`, `cos`, `tan`, `ln`, `exp` and `abs`.

**(3) Multipart**

| Field | Type | Meaning |
|---|---|---|
| `type` | string | Always `'multipart'` |
| `prompt` | string | Overall stem |
| `parts` | object[] | 2–8 sub-questions, each a numeric input item |
| `explanation` | string | Per-item explanation |

A multipart item counts as correct only when **every sub-question** is correct — a good fit for stepwise derivations.

Distribute correct-option positions; distractors and accepted answers should come from real misconceptions. The item type follows the stage 2 preference in [`AGENTS.md`](AGENTS.md), and explanation style follows it too.

## 4. Validation rules

Import is rejected when:

| Category | Rejection condition |
|---|---|
| Structure | Missing required fields, wrong types, incompatible `schemaVersion` |
| Course | Invalid ID format, non-positive `version`, empty `nodes` |
| Nodes | Duplicate IDs, missing parents, prerequisite cycle, more than 20 items, `passCount` greater than item count |
| Questions | Empty options / out-of-range `answer`; empty `answers` or invalid tolerance; fewer than 2 `parts`; missing explanation |
| Content | Overlong text, unknown block type |
| Packaging | Malformed ZIP, CRC mismatch, oversized file |

When rejected, **fix the source** rather than bypassing validation. Validation exists so that a lit node really corresponds to a complete unit of learning.

---

## 5. ZIP and generated artefacts

- The builder produces the ZIP containing the descriptor, node files and optional guide.
- `catalog.js` is the catalogue the site reads and **must not be hand-edited**; rebuild after source changes.
- Increment the version and rebuild before the site will treat content as newer.
- Keep generated files out of manual editing so the next build does not silently overwrite work.

---

## 6. Version replacement and progress

| Action | Effect on progress |
|---|---|
| Edit content but keep node IDs | Existing progress survives |
| Change or remove node IDs | Matching progress may break; warn the user first |
| Raise `version` | Site treats content as newer and supersedes |
| Import a different course | No overwrite; courses are separated by ID |

---

## 7. Relation to the answer mode

[`AGENTS.md`](AGENTS.md) requires the AI to ask how the user wants to answer. The preference maps directly onto an item type:

| Preference | Where it lands in the format |
|---|---|
| Multiple choice | `questions[].prompt` / `options` / `answer` |
| Numeric input | `type: 'input'` + `answers` + optional `tolerance` |
| Multipart | `type: 'multipart'` + `parts` |
| Mixed / custom | Mix the three types by node and record it in the handoff; confirm feasibility for custom approaches |

Choose the item type that matches the user's preference. Only for modes outside these three (for example spoken answers or grading uploaded handwriting) should the AI disclose the gap first, then apply the preference to wording and explanations. Never claim an unimplemented feature or invent fields that do not exist.


---

## 8. Checklist

- [ ] Both mandatory prompts from `AGENTS.md` completed
- [ ] `topic.json` has `schemaVersion`, an incremented `version`, and a clear `sourceNote`
- [ ] Every `parents` entry exists; no cycles
- [ ] Node IDs stable; long formulas explicitly broken into lines
- [ ] Item type matches the preference; `prompt` / `answers` / `parts` fields correct; explanations present
- [ ] `passCount` not greater than item count
- [ ] Builder and tests run; generated files untouched
- [ ] Import, unlock and progress persistence verified on the site
